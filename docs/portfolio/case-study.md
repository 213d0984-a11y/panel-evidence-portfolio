# Panel Evidence — 電気・製造業の資料確認を支援する

盤の設計・部品選定では、型式に対応する定格、使用環境、端子条件を複数のカタログや仕様書から探す作業が繰り返されます。似た型式や、一般性能と認証定格の違いを取り違えると、検索が速くても業務では使えません。

Panel Evidenceは、この確認作業を「質問→該当ページ→原文・表の値→原本確認」へまとめるローカルアプリです。単に関連文を返すだけでなく、根拠が足りないときに回答を控えることを重視しています。

低圧100/200V制御盤のハード設計での、客先仕様の読解・部品選定・回路設計・盤内配置・設計標準化・製造対応を背景に制作しました。開発者は実務課題の整理、要件判断、評価方針、原本照合と成果確認を担当し、実装・テスト作成・調査にはAI開発支援ツールを活用しています。

## 実務での使用例

1. 仕様書とセンサ取説を登録し、指定型式の電源電圧を確認する。
2. 電源カタログ2冊から、各型式の定格電流と出力電圧を横断確認する。
3. 端子台の型式列を確認し、適合電線やねじの値を原本と照合する。
4. 登録資料にない通信方式・未登録型式を尋ね、根拠不足の表示を確認する。

## 実装で判断したこと

意味検索に型式・キーワード検索を加え、固有名詞と表記揺れに対応しました。次に、短いチャンクだけでは表の見出しと値が分断されるため、ページ単位の根拠を復元しました。回答拒否を厳しくするだけでは実用性が落ちるため、検索側で必要な情報を揃える変更と、回答側で適用条件を確認する変更を組み合わせています。

未知資料で、電源端子のトルクを取付ねじに誤適用する問題が見つかりました。部位名が同じページに存在するだけでなく、仕様項目の近くで対応することを求め、回帰テストを追加しました。初回評価の失敗も記録しています。

共通仕様の誤拒否には、対象型式と仕様表の列を証明する処理を加えました。型式一覧の出力電圧と出力電流が同じ見出し内で一意に対応する場合だけ結び付け、対応ページと値のページを両方引用します。型式文字列を独自に復号して値を推測する方式ではありません。

原本の型式列を照合する過程で、既存の正解データにも値の不一致を発見しました。評価問題を都合よく直すのではなく、原本に従う回答と凍結正解との差を記録しています。検索指標の向上だけで回答の正確性を説明しないための判断です。

接点の比較では、抵抗負荷という語があるだけでは不十分でした。取付形式・極数・NO/NCと負荷列の明示的な対応を根拠にし、寿命条件の違う複数の定格を残しました。未知のCOSEL資料で発見した、長い説明の下の表や単位見出しの誤拒否も修復しました。その後コードを固定し、別メーカーのPhoenix Contact資料を初回評価しています。調整後の再試験と未調整の初回結果を混ぜません。

現在は小規模資料セット・単一利用者向けのポートフォリオ版です。固定28問では可否96.4%、不能拒否5/5、誤拒否1/23。167テストと追加実資料の評価を添えています。型式の別名、複雑な縦結合表、文章に分散した条件には制約が残ります。性能値を、全技術文書への完全な理解や設計判断の自動化として説明しません。

v0.5.1では、独立監査で見つかった電力・適用条件の誤拒否を修復しました。HDR-60は初回6/8から回帰再試験8/8へ改善しましたが、修正に使った資料なので「未知資料で8/8」とは宣伝しません。さらに、正しいページの提示と、対象型式に対応した直接値提示を別に測る指標を加えました。直接値提示は固定28問の回答可能23問中3問であり、全表提示を自動数値抽出の成功には数えていません。

この作品が示すのは、電気設計の現場で起きる取り違えを具体的な検証項目に落とし、検索・根拠提示・拒否の処理を改善し、その効果と限界を再現可能に説明する実装力です。

発注者は、資料検索や仕様確認などの業務をツール化する際の、課題整理から検証までの進め方を確認できます。顧客導入・売上・作業時間削減率を示す実績ではありません。[公開版の導入・安全性確認](public-release-check.md)に、第三者が試すための確認範囲をまとめています。

v0.5.2では、独立した新規依存環境で導入・全テスト・固定評価を再現し、実ブラウザの破損PDFエラーと再起動後の台帳／索引の整合まで確認しました。公開資料の権利と利用者の監査メモを守る配布処理も含め、動くだけでなく第三者へ渡すための検証を行っています。[引き渡し検証](handoff-v052.md)に確認範囲を記載しています。
